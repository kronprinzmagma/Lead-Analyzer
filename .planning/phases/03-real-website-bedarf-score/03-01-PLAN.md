## Sub-signal → dimension combination rule (Pattern 2, applies to BOTH dims, pin EXACTLY)
Classify each sub-signal as one of: `severe` / `gap` / `minor`. Then fold:
- **any** sub-signal `severe` → dimension = `"severe"`
- else **≥1** `gap` → dimension = `"gap"`
- else **≥2** `minor` → dimension = `"gap"`
- else → `"ok"`

The reason string = a compact German join of the firing (non-ok) sub-signal notes. If all ok, a short positive note.

## CRITICAL — no-HTML policy (reachable-but-no-body rows; pin EXACTLY)
A row can be reachable yet have NO parseable body (`fr.html is None`): WAF responses 403/406/429, or existence's "Antwort ohne lesbaren Body" gap. These rows are NOT dead (Dim 1 returns a `gap`, never `dead=True`). The aggregation (03-03) bands Bedarf from gap/severe counts, so an over-eager analyzer that returns `severe` on missing-HTML would push G/S high enough to land Bedarf 5 — violating the Phase-2 invariant **"403/blocked != Bedarf 5"**.

Therefore, when `soup is None` (no parseable body) on a NON-dead row:
- **Dim 4 (SEO, this plan):** return a NEUTRAL, non-scoring verdict that contributes **0 gap-points**:
  `DimensionVerdict(4, "ok", "nicht bewertbar (kein HTML)", "n/a")`. It MUST NOT return `severe`/`gap` merely because there is no body to read. (We don't over-rank a site whose SEO we literally cannot see.)
- **Dim 2 (Technische Basis, this plan):** STILL measurable without a body — HTTPS comes from the `final_url`/`url` scheme, SSL from `fr.ssl_ok`, free-subdomain from the host. Dim 2 needs NO HTML and therefore returns a real `ok`/`severe` even when `soup`/`html` is None.

Consequence (intentional, conservative): a WAF-blocked reachable site gets dim1=gap + dim2=measured + dims 3/4/5/6 neutral → typically a single gap-point → **Bedarf 2** (or 3 if Dim 2 also flags). The "!= 5" half of the invariant holds by construction.
