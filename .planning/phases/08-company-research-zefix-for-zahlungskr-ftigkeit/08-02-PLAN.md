## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| input row → Zefix lookup | untrusted `Kundenname`/`Kanton` cell values become the search query |
| ZefixFacts → score + run-log | authoritative-but-external data drives Group A points and the JSONL audit trail |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-07 | Tampering | name cell injection into lookup | mitigate | ZefixClient.lookup length-guards (≥3) and posts via `json=body` (08-01, T-08-03); pipeline passes the raw cell unmodified, no shell/SQL context |
| T-08-08 | Denial of Service | Zefix lookup stalls/aborts a row | mitigate | lookup never raises (08-01 contract); called outside the exception path only on normal/empty-url; per-row boundary + shared budget intact |
| T-08-09 | Repudiation | unverifiable score after the fact | mitigate | source_url + uid + status carried in PaymentEstimate.signals → RowResult.zahl_signals → existing JSONL run-log (NACH-01); confidence label distinguishes zefix vs heuristik |
| T-08-10 | Info Disclosure | credentials leak via signals/run-log | mitigate | only public fields (uid, legal_form, status, ehraid-derived URL) enter signals; creds never reach payment.py or the run-log |
| T-08-11 | Tampering | non-active company scored as viable | mitigate | _status_modifier penalizes CANCELLED/BEING_CANCELLED post-aggregation (clamped), so a deleted AG scores below an active GmbH (AC3) |
</threat_model>
